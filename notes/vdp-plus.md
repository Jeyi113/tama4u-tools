# VDP+ (Virtual Deco Pierce Plus) — 구조와 만드는 법

Mr.Blinky의 VDP+는 데코피어스 롬의 내용을 P's 다운로드로 옮긴 것이다.
꽂는 대신 적외선으로 받아 외출지 하나를 실행하면, 피어스를 꽂았을 때와 같은
설치가 일어난다. (코드: `tama4u/vdp.py`, 검증용 비교: 아래 "롬과의 대응")

## 1. 파일 구성

| 파일 | 패킷 목적지 | 역할 |
|---|---|---|
| `*-1-N.jpg` | `94 02 5B 02` (VDP 외출지) | 로더 스텁(S1C33 코드, `DecoPierce`) + 압축 스트림 앞부분 |
| `*-2-N.jpg` … | `81 09 29 00` (통신 레시피 선반) | 압축 스트림의 이어지는 조각 (0x108부터, 앞은 로더 머리말 복사본) |

- 다운로드 1개는 최대 32,768바이트. 그래서 스트림을 2~3개 파일로 나눈다.
- 파트 순서는 아이템명 끝 숫자(`CIRCUS…1/2/3`). 이어 붙이는 순서가 틀리면 풀리지 않는다.
- 각 파일 = JPEG 미리보기 + 패킷(머리말 0x100, 끝 2바이트 체크섬).

## 2. 압축 스트림 → payload

- 로더가 스트림을 풀어 펌웨어 슬롯에 설치한다. 압축 방식 2종(`vdp.unpack_rle`,
  `vdp.unpack` = LZ, 16비트 단위). VDP+는 LZ.
- 풀린 payload = **피어스 롬의 0x1000 이후와 같은 배치**:

```
payload 0x0000  피어스 머리말 4KB
         0x0A  외출지 이름 (문자 코드 8개)
         0x12  u32 추가 블록 크기 (로딩 아이콘 등)
         0x16  u32 캐릭터 영역 크기
         0x1B  u8  키울 캐릭터 수
         0x20~ 캐릭터 정보 블록 0x180씩
         0xF24 u16 x10 종류별 개수 (식사, 간식, 장난감, 아이콘, 액세, 옷, 게임, ?, 외출지, 리빙)
payload 0x1000~ [u16 길이][패킷]... 레코드 사슬 (아래 "내용물 사슬")
payload 0x1002~ 내용물 패킷들 (각각 보통의 P's 패킷과 같은 머리말 꼬리 + 데이터)
         81033300 키울 캐릭터 (14,664B 고정)   81071f00 리빙(방)
         81010101 로딩 아이콘                 81010201 식사 / 81010d02 간식
         81042a01 장난감                      81042902 메뉴 아이콘 세트
         81023400 액세서리                    81033300(작은 것) 옷
         94025b01 미니게임 프로그램            94024702 외출지 프로그램
```

## 3. 롬과의 대응 (2026-10-24 확인)

`payload[i] == rom[0x1000 + i]` 가 15개 중 15개에서 성립(차이 0.5~12%).
차이 = 영어판에서 바꾼 곳뿐:

- 머리말: 외출지 이름, 캐릭터 정보
- 아이템 패킷: 이름(0x5E~)과 체크섬(끝 2바이트)
- 외출지 프로그램: 대사 영역을 통째로 다시 배치 + 프로그램 앞쪽 오프셋 값
- 미니게임: 문구 + 글자가 그려진 그림
- `magical`은 롬이 없는 창작판(Tamagotchi Meets/On 소재)

## 4. 새 VDP+를 만드는 절차 (UI로 옮길 단계)

1. 피어스 롬에서 payload = `rom[0x1000 : 0x1000 + 길이]` 를 잘라낸다
   (또는 기존 VDP+의 payload를 푼다).
2. 바꿀 것을 고친다: 이름(고정 칸), 대사(외출지 대사 표 재배치, `outing.py`),
   그림(같은 크기면 제자리, 크기가 바뀌면 `outing.resize_sprite`).
   고친 패킷은 끝 2바이트 체크섬을 다시 계산한다.
3. `vdp.repack_split(part1, [part2, part3], payload)` — LZ로 다시 압축하고
   32,768바이트 단위로 잘라, 기존 파일의 로더·머리말을 그대로 붙인다.
4. 각 파일에 JPEG를 앞에 붙여 저장 (`container`), 파일 이름은 원래 규칙 유지.

모자라면 파트를 하나 더 만든다(레시피 선반 패킷 머리말 복사, 이름 끝 숫자 +1).

## 5. 내용물 사슬 (2026-10-24 확인)

- 각 패킷 앞 2바이트 = 레코드 길이 n (BE). 다음 레코드는 패킷 시작 + n.
  n은 패킷 크기를 `[u16][패킷]`이 4의 배수가 되게 올린 값(크기%4==0이면 +2).
- 앞부분(캐릭터 3개 0x39BA 간격, 로딩 아이콘·첫 거실 = 머리말 0x12 크기의 추가 블록)은
  고정 배치. 그 뒤부터 끝(FFFF)까지가 사슬이라 패킷이 커져도 u16만 고치면 된다.
- payload 길이·총 크기는 로더 어디에도 없다(스트림 끝까지 푼다).

## 6. 대사 위치

- 외출지(94024702)·미니게임(94025b01) 모두 프로그램 기준 주소 0x02000000.
  대사는 마지막 스프라이트 뒤. 코드가 `xld.w`로 직접 가리키거나(외출지),
  `xld.w` → LE32 포인터 표 → 문장(미니게임).
- 문자 코드 = 펌웨어 글꼴 코드(fwchars). 0xFF 줄바꿈, 0x00 끝. 한글 패치의
  `hangul_text.encode`가 그대로 통한다.
- 한글화: 새 문장을 패킷 끝에 붙이고 주소만 바꾼다(`tools/vdp_ko.py`).
- 이름 칸: 패킷 0x5E부터 0으로 끝, 10바이트까지(0x69는 다른 값).
